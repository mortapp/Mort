# MORT Remote Push Scheduler Implementation Plan

> **For agentic workers:** Execute inline in the current Mort worktree. Preserve the existing policy gates and all owner credentials.

**Goal:** Schedule the existing `send-push` Edge Function through Supabase Cron so queued remote notifications can run after owner configuration and explicit backend activation.

**Architecture:** `pg_cron` invokes one private Postgres helper every minute. The helper checks `private.push_delivery_available()`, reads the Supabase URL, anon JWT, and invoke secret from Vault, and queues a `pg_net` POST only when all prerequisites exist. FCM credentials remain in Edge Function secrets.

**Tech Stack:** Supabase Postgres 17, `pg_cron`, `pg_net`, Vault, pgTAP, Supabase Edge Functions, PowerShell/Flutter repo workflow.

**Spec:** `docs/superpowers/specs/2026-10-25-mort-push-scheduler-design.md`.

## Review Focus

- Release policy or runtime disabled: no outbound request is queued.
- Required Vault values absent: no outbound request is queued.
- Enabled database policy with wrong or unavailable credentials: no job event is claimed by the sender.
- Cron extension or schedule is already present: migration remains idempotent and leaves one named job.
- Scheduled request has both gateway JWT headers and the sender's independent custom invoke header.
