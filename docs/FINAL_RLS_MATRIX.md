## Profile column boundary

- Authenticated table-level SELECT on `profiles` is revoked.
- Directory-safe columns granted to authenticated users: `id`, `role`, `display_name`, `verification_status`, timestamps, `username`, avatar fields, `bio`, `availability`, preferred categories, approximate area, and goals.
- Sensitive columns denied through direct table SELECT: `dob`, exact `city/state`, onboarding/account state, payment preference, push token, restriction timestamp, guardian setup state, and test-account marker.
- `get_my_profile()` is caller-bound. `admin_list_profiles()` checks admin status. Their privileged bodies live in the non-exposed `private` schema.
- `protect_profile_sensitive_fields()` blocks client role, verification, restriction, and test-account escalation on both INSERT and UPDATE.

Storage conclusions:
- All four buckets are private. Anonymous list/download and unrelated-user list/download/overwrite checks passed.
- Paths are owner-prefixed. Proof and verification RPCs verify the caller, application/adult ownership, path, stored MIME, and stored size.
- Attached proof and verification evidence cannot be deleted or overwritten by the uploader. Admin moderation retains controlled access.
- Avatar display uses the authenticated `avatar-url` Edge Function and a one-hour signed URL. Original objects remain private.
- Flutter checks JPEG/PNG/WebP signatures, decodes pixels, bakes orientation, resizes, and re-encodes JPEG. Re-encoding removes source EXIF/GPS metadata; malformed signatures and oversized input are covered by Flutter tests.
- Bucket MIME allowlists are defense in depth. Storage metadata is not trusted by itself for client-side processing.

## Multi-user proof

- Teen A cannot read Teen B private profile columns or edit Teen B.
- Only the owning adult sees/manages an application; unrelated adults and teens see no proposal.
- Only thread participants read/send messages; outsiders and an optionally linked guardian cannot read unrestricted job messages.
- Active guardian visibility is relationship- and preference-bound; unlink immediately removes teen-profile and Safety Ping access.
- Direct helper-RPC probes for another guardian link, Safety Ping preference, account status, and block relation return false.
- Normal users cannot forge admin, verification, test-account, entitlement, purchase-audit, AI-audit, username-credit, or boost-credit state.
- Review insertion fails before completion and a duplicate same-side review fails after the first.
- Proof-required jobs reject premature completion with `proof_required`; valid `proof` wording publishes while explicit roof work remains safety-blocked.
- Saved jobs, support tickets/messages, blocks, notifications, and activity history remain owner/participant isolated.
- Test jobs are visible to QA accounts only and hidden from normal accounts.
- All eight disposable users and their cascaded rows were removed after the run; only the dedicated fixed `@mort.test` rebuild fixtures remain.

## Limits

- RLS and remote QA do not replace a legal/privacy/teen-safety review.
- Service-role behavior was used only for controlled fixture creation/cleanup and server-authoritative writes.
- Real iPhone, TestFlight, native camera/photo permission, push delivery, and App Store review were not performed.
