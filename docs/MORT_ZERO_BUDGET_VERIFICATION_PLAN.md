# MORT Zero-Budget Verification Plan

## Available without vendor spending

- Supabase email ownership confirmation
- secure-password and reset controls already configured
- hosted session monitoring and active-session summaries
- Swift local device reauthentication source
- server-derived trust profile and structured eligibility reasons
- approved-domain and hashed partner-code affiliation architecture
- allowlisted official business-registry manual review architecture
- private appeals, risk reasons, expiry/revocation, least-privilege queues, and audit events
- sandbox QA isolated from production

## Deliberately unavailable

- public marketplace participation for ordinary production users
- phone OTP in the current hosted Auth configuration
- passkey enrollment under the current server flag/configuration
- real identity-document collection
- Apple/Android government digital credentials
- provider-backed legal identity and age verification
- adult screening/background checks
- automated registry scraping

Zero-budget signals must never be relabeled as authoritative identity. Guardian Mode stays optional. A closed pilot requires written legal/safety policy, trained reviewers, incident operations, approved participants, clear disclosures, and a new reviewed server policy even if no vendor is purchased.
