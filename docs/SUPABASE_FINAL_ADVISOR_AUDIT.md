## P0/P1 issues fixed

- Private profile fields were readable through broad table SELECT grants. Authenticated access is now safe-column-only; callers use `get_my_profile()` and admins use `admin_list_profiles()`.
- Profile INSERT could self-assign admin/approved/test state. The profile protection trigger now covers INSERT and UPDATE and permits only trusted internal/admin changes.
- Attached proof and verification evidence could be overwritten through generic Storage UPDATE. Evidence objects are append-only for users; moderation updates are admin-only.
- Proof and verification RPCs now verify owner-prefixed paths plus Storage MIME and size metadata.
- Application submission, acceptance, proof, and completion now use a consistent parent-job-first lock order; proof-required completion is enforced.
- The job safety scanner now matches `roof` as a whole word, so legitimate `proof` wording is accepted while prohibited roof work remains blocked.
- Five helper RPCs no longer disclose arbitrary users' active, guardian, Safety Ping, pause, or block state; parameters are bound to the caller/admin/active relationship.
- Nine legacy policies declared for `public` were narrowed to `authenticated`, removing reliance on table grants as the only anonymous barrier.
- `conversation_participants` and `saved_jobs` circular policies were repaired after real remote QA reproduced PostgreSQL recursion errors.
- All 43 repeated `auth.uid()` advisor warnings were fixed with scalar subqueries, and all 40 overlapping permissive-policy warnings were consolidated or split by command.
- Twenty-four priority FK/ownership indexes were added; seven low-volume attribution FKs remain documented INFO findings.

**Classification: DEFERRED — PLAN-LIMITED SECURITY ENHANCEMENT**

This is not classified as an unresolved application-code security defect, and no plan upgrade or paid action is authorized in this pass.

Current mitigations:

- strong password minimum length
- required password complexity
- Auth rate limiting
- email verification
- RLS
- account restriction logic
- secure password reset flow

Future upgrade task:

> When Supabase is upgraded to Pro, enable leaked-password protection immediately and rerun Auth security advisors.
