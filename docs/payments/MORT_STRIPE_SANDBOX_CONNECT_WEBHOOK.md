These steps are for **Mort sandbox** (`acct_1TvorjJmJ5J7gUVQ`, `livemode=false`) and the **mort-p-backend-test** Supabase project (`ckcxakhxqlkhppsxxjhv`). Do not use the live Mort account or the test-mode view of that account. MORT already has a sandbox Connect destination; verify it before creating anything.

## Configure through the Stripe connector

1. Use the existing Stripe connection and list the available accounts. Select **Mort sandbox** and pass its account ID and `livemode: false` on every Stripe operation. Check existing webhook endpoints for this exact QA URL and confirm the event source is **Connected accounts** (`@accounts`). The last verified matching name was `MORT QA ckcxakhxqlkhppsxxjhv - Connect signed snapshots`.
2. If the destination is missing, use the connector’s webhook endpoint creation operation (`POST /v1/webhook_endpoints`) with `connect: true`, the URL `https://ckcxakhxqlkhppsxxjhv.supabase.co/functions/v1/stripe-webhook`, and exactly `account.updated`, `payout.created`, `payout.updated`, `payout.paid`, `payout.failed`, and `payout.canceled`. This endpoint expects signed snapshot events. Do not subscribe it to `*` or send Accounts v2 thin events to it ([Stripe Connect webhooks](https://docs.stripe.com/connect/webhooks?locale)).
3. Only when provisioning or rotating the endpoint, store its signing secret as `STRIPE_TEST_CONNECT_WEBHOOK_SECRET` in [Supabase Edge Function Secrets for mort-p-backend-test](https://supabase.com/dashboard/project/ckcxakhxqlkhppsxxjhv/functions/secrets). Keep it distinct from `STRIPE_TEST_WEBHOOK_SECRET`, the platform endpoint’s secret. Do not paste secret values into chat, PRs, terminal output, or test evidence. If no secure storage path is ready, leave the new destination disabled ([Stripe webhook signing](https://docs.stripe.com/webhooks#verify-webhook-signatures)).
4. Read back the account, mode, URL, source and event list before enabling the destination. Trigger a genuine sandbox `account.updated` or payout lifecycle event using a synthetic fixture, and confirm that MORT accepts the signature and records the expected Connect outcome. A registration, a local signature test, or a successful platform delivery is not proof of signed Connect delivery ([Stripe Connect testing](https://docs.stripe.com/connect/testing)).

## Launch boundary

The last verified hosted test showed one signed platform cancellation, not a signed Connect delivery. The current sandbox rejected MORT’s former Accounts v1 creation request. The Accounts v2 code candidate uses only synthetic U.S. recipient fixtures and does not collect or send a real profile’s email, identity documents, date of birth, or guardian consent ([Stripe recipient account configuration](https://docs.stripe.com/connect/marketplace/tasks/create)).

A provider-backed sandbox test, the approved guardian and account representative arrangement, full financial reconciliation, live signing verification, and explicit live-owner approval are still required before production activation. Transfers and payouts have separate gates. A Stripe onboarding return URL is not evidence that requirements were satisfied ([Stripe-hosted onboarding](https://docs.stripe.com/connect/marketplace/tasks/onboard), [Stripe guardian requirements](https://support.stripe.com/questions/age-requirement-to-create-a-stripe-account)).
